### Image/package evidence

The first streamed `docker image save` covering all 10 distinct deployed image IDs
completed successfully (exit 0). Nested tar layers were inspected, not extracted
or executed. This includes base layers and the old provisioning image, not just
the process currently running. Relevant-looking files in Paperless were Python
Pygments PHP syntax lexers, a protobuf PHP code-generator C++ header and MIME
metadata; none is a PHP interpreter. `ttGlyphPen.py` was also a substring false
positive, not PHP.

Small `docker cp ... -` reads independently checked actual `/etc/os-release` and
installed package databases for all 12 containers, including stopped jobs.
Debian `/var/lib/dpkg/status` and Alpine `/lib/apk/db/installed` had no installed
PHP/FrankenPHP/LiteSpeed packages. Keycloak has no `rpm` CLI: its 10,797,056-byte
RPM SQLite database was read without modification. Its single case-insensitive
`php` text occurrence is the readline upstream URL
`https://tiswww.case.edu/php/chet/readline/rltop.html`, not a PHP package.
Absence was corroborated by full layer file-name checks and executable probes.

`dpkg-query` reports `php-crypt-gpg` / `phpgacl` with status **un** in some queries;
these are uninstalled/unknown entries with no installed version, not PHP runtime.
Alpine's missing cached APKINDEX warnings were not used as absence evidence;
the installed database was read directly instead.

Trivy, Grype, Syft and Docker Scout were unavailable. None was installed and no
new SBOM infrastructure was introduced. This is a manual targeted inventory,
not a full vulnerability scanner certification.

### Operational observation: Docker save temporary disk use

Before audit: 6.2 GiB free (not the historical 10 GiB). Although the archive was
streamed rather than deliberately saved to a file, Docker daemon export staging
temporarily consumed the remaining root filesystem space during repeated
all-image reading. One concurrent `status.sh` encountered ENOSPC creating a shell
temporary file. The second inventory invocation also failed in its final summary
because host Python 3.8 lacks `str.removesuffix`; it was not treated as successful
evidence. The first complete scan and small direct package reads are the evidence.

The diagnostic process ended, Docker released its temporary data automatically,
and the subsequent scoped cancellation check found no remaining audit process
to terminate. Root free space returned to 6.2 GiB; final `status.sh` passed.
No manual deletion or prune was used. Do **not** repeat all-image save on this
small disk: prefer bounded direct file/package reads, or obtain approved extra
capacity before a future full scanner/export. This is an operational capacity
risk, not a PHP CVE finding.
